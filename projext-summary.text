สรุปโครงการ Smart City Complaint Center

ระบบรับและติดตามเรื่องร้องเรียนผ่าน LINE OA พร้อมหน้าปฏิบัติงานสำหรับเจ้าหน้าที่
รองรับการจัดหมวดหมู่ มอบหมายหน่วยงาน ติดตามสถานะ รูปภาพ แผนที่ รายงาน
การกำกับดูแลผู้ใช้งาน และ Audit Log

ประวัติการแก้ไขล่าสุด

4 สิงหาคม 2569
- เพิ่มสิทธิ์ DEV ในฐานข้อมูลด้วย migration 019_add_dev_role.sql
- DEV มีสิทธิ์จัดการระบบเทียบเท่า Admin รวมถึงดูและแก้ไขทุกหน่วยงาน
- DEV สามารถเพิ่ม แก้ไข และลบผู้ใช้งาน รวมถึงสร้าง Admin ได้ แต่สร้าง DEV เพิ่มผ่านหน้าเว็บไม่ได้
- คำสั่ง scripts/create-admin.js ใช้สร้าง DEV ครั้งแรกหรือรีเซ็ต DEV บัญชีเดิมได้ โดยไม่อนุญาตให้มี DEV คนที่สอง
- เพิ่มการทดสอบยืนยันว่า DEV ผ่านจุดตรวจสิทธิ์ระดับผู้ดูแลระบบ
- ปรับเวอร์ชันไฟล์ admin.js เพื่อให้เบราว์เซอร์โหลดโค้ดสิทธิ์ใหม่
- ไม่บันทึกรหัสผ่านหรือสร้างบัญชี DEV อัตโนมัติใน Source code
- Dashboard ของ Admin และ DEV แสดงจำนวนบัญชี Backend ที่เปิดใช้งานเทียบกับทั้งหมด
- Dashboard ของ Admin และ DEV แสดงหน่วยงานที่มีกิจกรรมใน Audit Log สูงสุดในช่วง 30 วัน
- ซ่อนสถิติผู้ใช้งาน Backend จาก Officer, Supervisor และ Executive

4 สิงหาคม 2569 (จำกัดบัญชี DEV)
- นำตัวเลือก DEV ออกจากหน้าสร้างผู้ใช้งาน ทำให้ Admin และ DEV สร้าง DEV เพิ่มผ่านหน้าเว็บไม่ได้
- API ปฏิเสธการสร้างหรือแต่งตั้งผู้ใช้งานทั่วไปเป็น DEV แม้เรียก API โดยตรง
- Admin ไม่สามารถแก้ไขบัญชี DEV และระบบไม่อนุญาตให้ลบบัญชี DEV
- เพิ่ม migration 020_limit_single_dev.sql เพื่อบังคับให้ฐานข้อมูลมีบัญชี DEV ได้สูงสุด 1 บัญชี
- ปรับเวอร์ชันไฟล์ admin.js เพื่อให้เบราว์เซอร์โหลดหน้าจัดการสิทธิ์ล่าสุด

4 สิงหาคม 2569 (Dashboard ผู้ใช้งาน)
- เพิ่มการ์ด USER STATUS ถัดจาก CASE STATUS สำหรับ Admin และ DEV
- USER STATUS แสดงจำนวนบัญชีที่เข้าใช้ใน 30 วัน บัญชีที่ยังไม่เข้าใช้ใน 30 วัน และบัญชีที่ถูกระงับ
- เพิ่มการ์ด TOP USER DEPARTMENTS แสดงจำนวนผู้ใช้งาน Backend ที่เข้าใช้ในแต่ละหน่วยงานช่วง 30 วัน
- ปรับการ์ดหน่วยงานเข้าใช้มากที่สุดให้แสดงจำนวนคนแทนจำนวนกิจกรรม
- ข้อมูลสถิติผู้ใช้งานยังคงซ่อนจาก Officer, Supervisor และ Executive

5 สิงหาคม 2569

- ปรับเวอร์ชัน styles.css เพื่อบังคับให้เบราว์เซอร์และ LINE โหลดรูปแบบโลโก้ล่าสุด

6 สิงหาคม 2569
- เปลี่ยนตัวอักษร SC บริเวณ Sidebar ของหน้าเจ้าหน้าที่เป็นตราเทศบาลนครสุราษฎร์ธานี
- ใช้ไฟล์ assets/suratcity-logo-bigsize-w5983xh5983-trans.png และคงขนาดตำแหน่งแบรนด์เดิม
- เพิ่มเปอร์เซ็นต์ในกราฟ CATEGORY INSIGHT และ DEPARTMENT INSIGHT โดยแสดงจำนวนจริงพร้อมสัดส่วน
- ปรับความยาวแท่งกราฟ Analytics ให้ตรงกับเปอร์เซ็นต์ของข้อมูลรวม
- ปรับเวอร์ชัน admin.js เพื่อให้เบราว์เซอร์โหลดกราฟรูปแบบล่าสุด
- เพิ่มคำอธิบายสีหมุดสถานะในพื้นที่ด้านขวาของหัวข้อ Smart Map
- คำอธิบายครอบคลุม รับเรื่องใหม่ รับเรื่องแล้ว มอบหมายแล้ว กำลังดำเนินการ และเสร็จสิ้น
- ปรับ Legend ให้ตัดบรรทัดอัตโนมัติและแสดงใต้หัวข้อบนหน้าจอมือถือ
- แก้สีวงกลม Legend ไม่แสดงจาก Content Security Policy โดยเปลี่ยนจาก inline style เป็น CSS class
- เปลี่ยนพื้นหลังส่วนหัวรายละเอียดเรื่องร้องเรียนจากสีเขียวเป็นม่วงพาสเทล
- ปรับข้อความในส่วนหัวรายละเอียดเป็นม่วงเข้มเพื่อให้อ่านชัดเจน
- ปรับกราฟ CATEGORY INSIGHT และ DEPARTMENT INSIGHT เป็นกราฟแท่งแบบจัดอันดับพร้อมป้ายจำนวนและเปอร์เซ็นต์
- เพิ่มสีม่วงพาสเทลหลายเฉด เอฟเฟกต์เมื่อชี้ และรูปแบบที่อ่านง่ายบนมือถือ
- เปลี่ยนแท่งกราฟเป็น progress element เพื่อให้ความยาวกราฟทำงานภายใต้ Content Security Policy
- รวมการแนบรูป เลือกสถานะ หมายเหตุ และแจ้ง LINE ให้เหลือปุ่มเดียว “บันทึกสถานะและแจ้ง LINE”
- เพิ่มส่วนกำลังดำเนินการและเสร็จสิ้น พร้อมแยกรูปผลการทำงานตามสถานะ
- เพิ่ม migration 021_add_work_attachment_phase.sql สำหรับบันทึกสถานะของรูปเจ้าหน้าที่
- ยกเลิกการเปลี่ยนสถานะอัตโนมัติจากการอัปโหลดรูป และใช้สถานะที่เจ้าหน้าที่เลือกก่อนบันทึกแทน
- รูปเก่าของเรื่องที่เสร็จสิ้นก่อนมีระบบแยกรูปจะแสดงในส่วนเสร็จสิ้น และไม่อนุญาตให้ย้อนกลับเป็นกำลังดำเนินการ
- ปรับคำบนหน้าจอและข้อความระบบให้แสดงเพียง “กำลังดำเนินการ” และ “เสร็จสิ้น”
- เปลี่ยนส่วน “การดำเนินงาน” เป็น “มอบหมาย” พร้อมปรับชื่อปุ่มและช่องหมายเหตุให้สอดคล้องกัน
- เมื่อมอบหมายหรือเปลี่ยนหน่วยงาน ระบบเปลี่ยนสถานะเป็น “มอบหมายแล้ว” และแจ้งประชาชนผ่าน LINE; หากยังไม่มอบหมายหรือหน่วยงานไม่เปลี่ยนจะไม่ส่งข้อความซ้ำ
- ตรวจสิทธิ์และลำดับการเปลี่ยนสถานะซ้ำภายใน Transaction เพื่อป้องกันข้อมูลเปลี่ยนพร้อมกัน
- ผลการบันทึกจะแจ้งตามจริงว่า LINE ส่งสำเร็จหรือบันทึกสำเร็จแต่ส่ง LINE ไม่สำเร็จ
- หากบันทึกสำเร็จแต่ส่ง LINE ไม่สำเร็จ หน้าจอจะแสดงข้อความเตือนสีแดงแทนข้อความสำเร็จ
- แก้ปุ่ม “แจ้งเรื่องใหม่” ให้คงชื่อผู้แจ้งจากบัญชี LINE หลังรีเซ็ตฟอร์ม พร้อมล็อกช่องชื่อและบันทึกชื่อจาก LINE ที่ฝั่งเซิร์ฟเวอร์
- ซ่อนข้อความชื่อเจ้าหน้าที่ เช่น “โดย ผู้ดูแลระบบ” ใต้รูปผลการดำเนินงานในหน้าติดตามเรื่องของประชาชน โดยยังแสดงหมายเหตุของรูปตามเดิม
- เพิ่มลิงก์ “ติดตามเรื่อง” เหนือเลขรับเรื่องในข้อความแจ้งเตือน LINE ทุกประเภท เมื่อแตะแล้วหน้า LINE User จะเปิดแท็บติดตามเรื่องอัตโนมัติ
- เพิ่ม migration 022_create_staff_profiles.sql เพื่อสร้างตาราง staff_profiles แบบอิสระ สำหรับเก็บชื่อเจ้าหน้าที่, LINE ID และเบอร์โทรศัพท์ โดยไม่เชื่อมกับ staff_users
- เพิ่มแท็บ “ข้อมูลเจ้าหน้าที่” พร้อมฟอร์มชื่อ–สกุล, LINE ID และเบอร์โทร รวมถึงรายการและปุ่มแก้ไข โดยใช้ API ของ staff_profiles แยกจากผู้ใช้งานระบบ
- จำกัดแท็บ ข้อมูล และ API ของ staff_profiles ให้เฉพาะบัญชี DEV เท่านั้น โดย Admin และสิทธิ์อื่นไม่เห็นและไม่สามารถเรียกใช้งานได้
- เพิ่มข้อมูล “ตำแหน่ง” ในตาราง staff_profiles ฟอร์ม DEV รายการแสดงผล และ API เพิ่ม/แก้ไขข้อมูลเจ้าหน้าที่
- คืน migration 022 ให้ตรงกับ checksum ที่เคยใช้งาน และย้ายการเพิ่มคอลัมน์ตำแหน่งไป migration ใหม่ 023_add_staff_profile_position.sql เพื่อรองรับฐานข้อมูลที่ติดตั้ง 022 แล้ว
- เพิ่ม migration 024_link_staff_profiles_to_departments.sql เพื่อเชื่อม staff_profiles กับ departments โดยไม่เชื่อม staff_users พร้อมเพิ่มตัวเลือกและคอลัมน์หน่วยงานในหน้า DEV
- ปรับข้อมูลเจ้าหน้าที่ให้ LINE ID และเบอร์โทรศัพท์เป็นข้อมูลไม่บังคับ โดยค่าว่างจะบันทึกเป็น NULL และหน้า DEV จะแสดงเครื่องหมาย - เมื่อไม่มีข้อมูล
- เพิ่มให้ DEV ลบข้อมูลเจ้าหน้าที่ได้ผ่านปุ่มลบและป็อปอัพยืนยัน โดย API ตรวจสิทธิ์ซ้ำ บันทึก Audit Log และรองรับการแตะพื้นหลังเพื่อปิดป็อปอัพ
- เพิ่มการมอบหมายเจ้าหน้าที่จาก staff_profiles ให้เรื่องร้องเรียน โดยกรองรายชื่อตามหน่วยงาน แสดงชื่อ–สกุล ตำแหน่ง และเบอร์โทรในรายละเอียด พร้อมแจ้งประชาชนผ่าน LINE เมื่อการมอบหมายเปลี่ยนแปลง
- เพิ่มการแสดงตำแหน่งเจ้าหน้าที่ในรายการเลือกผู้รับผิดชอบและในส่วนเจ้าหน้าที่ผู้รับผิดชอบของหน้ารายละเอียดเรื่องร้องเรียน
